# 10. どのテストを選ぶか

## 目的

この教材では、すべての振る舞いを同じ種類のテストで表しません。Hspecの具体例、QuickCheckの性質、実ファイルを使う統合テストを、それぞれが最も小さな証拠になる場所で使います。

## 最初のテスト

テスト選択も、最小の仕様から始めます。たとえば `myReverse [1,2,3] == [3,2,1]` は理解しやすい具体例です。その後で「二度反転すると元へ戻る」をQuickCheckで表します。ファイル保存は、変換ロジックを純粋関数で先に検証し、最後に一時ファイルで一回だけ往復します。

## 完成実装の場所

| テストの目的 | 主なテスト | 実装 |
|---|---|---|
| 具体的な仕様・境界値 | `test/Spec.hs` のHspec例 | `src/HaskellTdd/*.hs` |
| 多数の入力で成り立つ性質 | `test/Spec.hs` のQuickCheck property | `Fundamentals.hs` |
| 外部境界の接続 | `test/Spec.hs` の一時ファイルテスト | `TodoStore.hs` |
| 依存の差し替え | `IORef` を使う手書きスパイ | `Report.hs` |

## 型エラーをどう扱うか

未定義の関数や型が合わない式で止まったら、すぐに完成コードを参照しません。まず、GHCが示す期待型、実際の型、問題の式を確認します。次に、シグネチャを小さく書き直すか、入力と出力の例を一つに絞り、次のコンパイルエラーまたはテスト失敗を観測します。

## 次に増やす振る舞い

`Todo` のエンコードとデコードについて、タイトルに許可する文字を制限した生成器を作り、QuickCheckの往復性テストへ広げてください。外部境界の失敗は、純粋なパースエラーとIO例外を混同しないよう別々にテストします。

## 実行

```bash
cabal test --offline --test-show-details=direct
```
