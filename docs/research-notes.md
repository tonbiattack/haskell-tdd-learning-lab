# 教材拡張の調査と設計判断

## 参照した既存教材

今回の拡張では、ユーザー所有の `tdd-java-spring-learning`、`php-tdd-learning`、`nestjs-tdd-reading-list` を構成の参考にした。これらはいずれも、基礎・アプリケーション・補足の三群を分け、各実装済み章でガイド、完成実装、振る舞いテストを対応させている。また、依存の差し替え、実ファイルを使う最低一つのI/O検証、HTTPやアプリケーション境界といった、純粋な基本問題の次に学ぶ境界を明示している。

参照したリポジトリの文章やコードは複製しない。Haskellでは、オブジェクトやインターフェースをそのまま移植せず、代数的データ型、`newtype`、`Either`、関数引数による依存注入、IO境界の薄いラッパーに置き換える。

| 参照から得た設計上の問い | Haskell教材での表現 | 追加する証拠 |
|---|---|---|
| 不変条件を値オブジェクトへ閉じ込める | `mkUserName` と `mkAge` によるスマートコンストラクタ | 空名・範囲外年齢・成功値のHspecテスト |
| 外部I/Oを統合テストで検証する | 純粋なTSVエンコード/デコードと薄いファイル読書き関数 | 一時ファイルを使う保存・読込テスト |
| 依存をテストで差し替える | 出力関数を引数として受け取る `runReport` | `IORef` を使う手書きスパイ |
| 学習順序を明示する | `haskell-fundamentals/`、`build-an-application/`、`questions-and-answers/` | README、SUMMARY、対応表のリンク検査 |
| テスト種別を選択する | 具体例、QuickCheck、I/O統合の役割を補足章で説明する | `questions-and-answers/10-test-strategy.md` |

## 採用範囲

既存の第1〜6章は基礎群として維持し、章ガイドを `haskell-fundamentals/` へ移す。第7章で不正状態を型の構築段階から減らすスマートコンストラクタを扱う。第8章ではTODOのTSV保存を題材に、`renderTodos` と `parseTodos` を純粋に保ち、`saveTodos` と `loadTodos` をIO境界に限定する。第9章では、出力先を関数引数として渡す最小の依存注入を扱う。第10章は、Hspec、QuickCheck、統合テストの使い分けと、型エラーを観測して次の最小実験を選ぶ補足章とする。

この設計により、初期版で「部分実装」だった年齢の不変条件と、「未着手」だったファイルI/O・アプリケーション境界を、説明・実装・テストの揃った章へ昇格させる。
